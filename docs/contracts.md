# Контракты взаимодействия модулей

В этом документе описаны протоколы взаимодействия между модулями системы учёта товаров на складе.

Каждый протокол содержит:

1. инициатора и получателя;
2. назначение;
3. транспорт или механизм вызова;
4. точку входа;
5. формат запроса;
6. формат успешного ответа;
7. ошибки и их представление;
8. таймаут;
9. правила повторной отправки;
10. требования к аутентификации;
11. версию контракта;
12. пример обмена.

---

## Протокол № 1. Регистрация прихода товара (Оприходование)

### 1. Инициатор и получатель

- **Инициатор:** `MovementModule`
- **Получатель:** `InventoryModule`

### 2. Назначение

Протокол используется при проведении документа поступления. Необходимо увеличить остаток товара на указанном складе.

### 3. Механизм вызова

Асинхронный вызов через интерфейс C#: `IStockUpdateService`.
Зависимость передаётся через механизм Dependency Injection.

### 4. Точка входа

```csharp
Task<StockUpdateResult> AddStockAsync(
    AddStockRequest request,
    CancellationToken cancellationToken);
```

### 5. Формат запроса

```json
{
  "itemId": "8939af05-2a59-4758-a263-75df01c6d3f0",
  "warehouseId": "4f7fb20d-b92c-4082-a031-7eb643216a18",
  "quantity": 50.00,
  "movementDocumentId": "11223344-5566-7788-99aa-bbccddeeff00"
}
```

### 6. Формат успешного ответа

```json
{
  "success": true,
  "newBalance": 150.00,
  "errorCode": null
}
```

### 7. Ошибки

| Код | Описание |
|-----|----------|
| `ITEM_NOT_FOUND` | Товар не существует |
| `WAREHOUSE_NOT_FOUND` | Склад не существует |
| `INVALID_QUANTITY` | Количество меньше или равно нулю |

Пример ответа с ошибкой:

```json
{
  "success": false,
  "newBalance": 0,
  "errorCode": "ITEM_NOT_FOUND"
}
```

### 8. Таймаут

Операция должна завершиться не более чем за **2 секунды**.

### 9. Повторная отправка

Автоматический повтор не выполняется.
Повтор возможен только при ошибке таймаута, с предварительной проверкой статуса документа.

### 10. Аутентификация

Внутренняя аутентификация не требуется (вызов между модулями одного процесса).

### 11. Версия контракта

`StockUpdateContract v1`

### 12. Пример обмена

**Запрос:**

```json
POST /internal/stock/add
{
  "itemId": "8939af05-2a59-4758-a263-75df01c6d3f0",
  "warehouseId": "4f7fb20d-b92c-4082-a031-7eb643216a18",
  "quantity": 50.00,
  "movementDocumentId": "11223344-5566-7788-99aa-bbccddeeff00"
}
```

**Ответ (успех):**

```json
{
  "success": true,
  "newBalance": 150.00,
  "errorCode": null
}
```

## Протокол № 2. Регистрация расхода товара (Отгрузка)

### 1. Инициатор и получатель

- **Инициатор:** `MovementModule`
- **Получатель:** `InventoryModule`

### 2. Назначение

При проведении документа отгрузки необходимо проверить достаточность остатка и уменьшить его.

### 3. Механизм вызова

Асинхронный вызов через интерфейс: `IStockUpdateService`.

### 4. Точка входа

```csharp
Task<StockUpdateResult> DeductStockAsync(
    DeductStockRequest request,
    CancellationToken cancellationToken);
```

### 5. Формат запроса

```json
{
  "itemId": "8939af05-2a59-4758-a263-75df01c6d3f0",
  "warehouseId": "4f7fb20d-b92c-4082-a031-7eb643216a18",
  "quantity": 10.00,
  "movementDocumentId": "aabbccdd-1122-3344-5566-778899001122"
}
```

### 6. Формат успешного ответа

```json
{
  "success": true,
  "newBalance": 140.00,
  "errorCode": null
}
```

### 7. Ошибки

| Код | Описание |
|-----|----------|
| `ITEM_NOT_FOUND` | Товар не существует |
| `INSUFFICIENT_STOCK` | Недостаточно товара на складе |
| `INVALID_QUANTITY` | Некорректное количество |

Пример ответа с ошибкой:

```json
{
  "success": false,
  "newBalance": 0,
  "errorCode": "INSUFFICIENT_STOCK"
}
```

### 8. Таймаут

Максимальное ожидаемое время выполнения: **2 секунды**.

### 9. Повторная отправка

Не допускается. При ошибке `INSUFFICIENT_STOCK` документ расхода не проводится.

### 10. Аутентификация

Внутренняя аутентификация не требуется.

### 11. Версия контракта

`StockUpdateContract v1`

### 12. Пример обмена

**Запрос:**

```json
POST /internal/stock/deduct
{
  "itemId": "8939af05-2a59-4758-a263-75df01c6d3f0",
  "warehouseId": "4f7fb20d-b92c-4082-a031-7eb643216a18",
  "quantity": 10.00,
  "movementDocumentId": "aabbccdd-1122-3344-5566-778899001122"
}
```

**Ответ (успех):**

```json
{
  "success": true,
  "newBalance": 140.00,
  "errorCode": null
}
```

**Ответ (ошибка — недостаточно товара):**

```json
{
  "success": false,
  "newBalance": 0,
  "errorCode": "INSUFFICIENT_STOCK"
}
```

## Общий сценарий создания документа расхода

После определения протоколов процесс отгрузки выглядит следующим образом:

```
Клиент
    │
    │ Запрашивает отгрузку
    ▼
  ApiHost
    │
    ▼
  MovementModule
    │
    ├──────────────► CounterpartyModule
    │                 Проверка контрагента
    │
    ├──────────────► CatalogModule
    │                 Проверка существования товара
    │
    ├──────────────► InventoryModule
    │                 Проверка остатка и списание
    │
    │ Создание MovementDocument
    │
    └──────────────► (Сохранение в БД)
```

Результатом операции является проведённый документ расхода и уменьшенный остаток товара.

## Связь с моделями DTO

Описанные протоколы используют следующие DTO, определённые в проекте `WarehouseInventory.Contracts`:

- `RegisterReceiptRequest` — запрос на оприходование;
- `RegisterShipmentRequest` — запрос на отгрузку;
- `MovementResult` — результат проведения документа;
- `MovementDocumentDto` — представление проведённого документа.

Полное описание DTO приведено в разделе 9 основной документации проекта.
