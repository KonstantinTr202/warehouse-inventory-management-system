## 3. Отладка дефекта №1: Некорректный код ошибки при недостатке остатка

1. **Симптом:** При попытке отгрузить больше товара, чем есть на складе, API возвращает общую ошибку `"ERROR"`, хотя по утвержденному контракту (`docs/contracts.md`) должен возвращаться конкретный код `"INSUFFICIENT_STOCK"`.
2. **Версия/коммит:** `a1b2c3d` (ветка `feature/stage3-api`).
3. **Условия воспроизведения:** Отправка POST-запроса на `/api/Movement/shipment` с `"quantity": 999`, при текущем остатке `10`.
4. **Гипотезы:** 
   - Гипотеза А: Ошибка возникает на уровне middleware ASP.NET Core до попадания в сервис.
   - Гипотеза Б: В коде сервиса `StockUpdateService` захардкожено возвращение общего статуса ошибки вместо специфичного.
5. **Инструмент диагностики:** Точка останова (Breakpoint) в Visual Studio внутри метода `DeductStockAsync` на строке возврата результата.
6. **Наблюдаемый факт:** Отладчик показывает, что при срабатывании условия `_currentBalance < request.Quantity` создается объект `StockUpdateResult` с `ErrorCode = "ERROR"`.
7. **Исправление:** Значение свойства `ErrorCode` изменено с `"ERROR"` на `"INSUFFICIENT_STOCK"` в соответствии с контрактом.
8. **Регрессионный тест:** В `StockUpdateServiceTests.cs` добавлена строгая проверка: `Assert.Equal("INSUFFICIENT_STOCK", result.ErrorCode);`
9. **Повторная сборка и тестирование:** `dotnet build` (0 ошибок), `dotnet test` (все тесты пройдены).
10. **Вывод:** Симптом (некорректный ответ клиенту) был вызван невнимательностью при первоначальной реализации, а не сложной логической ошибкой. Контрактная дисциплина требует строгих кодов ошибок.

## 4. Отладка дефекта №2: Логическая ошибка при оприходовании (перезапись остатка)

1. **Симптом:** После успешного оприходования товара итоговый остаток на складе равен количеству поступившего товара, а не сумме старого и нового остатка.
2. **Версия/коммит:** `d4e5f6g` (ветка `feature/stage3-api`).
3. **Условия воспроизведения:** Изначальный остаток = 10. Отправка POST-запроса на `/api/Movement/receipt` с `"quantity": 50`. Ожидаемый остаток: 60. Фактический остаток: 50.
4. **Гипотезы:**
   - Гипотеза А: База данных (или эмуляция) не сохраняет предыдущее состояние перед обновлением.
   - Гипотеза Б: В коде используется оператор присваивания (`=`) вместо оператора сложения с присваиванием (`+=`).
5. **Инструмент диагностики:** Точка останова (Breakpoint) в Visual Studio внутри метода `AddStockAsync` на строке изменения баланса.
6. **Наблюдаемый факт:** При достижении точки останова на строке `_currentBalance = request.Quantity;` отладчик показывает, что старое значение `_currentBalance` (10) теряется, и переменная принимает новое значение (50).
7. **Исправление:** Строка изменена на `_currentBalance += request.Quantity;` — теперь новый остаток корректно прибавляется к старому.
8. **Регрессионный тест:** В `StockUpdateServiceTests.cs` добавлен тест `AddStock_ValidQuantity_IncreasesBalance`, проверяющий, что после оприходования 20 единиц к начальному остатку 10 итоговый баланс равен 30.
9. **Повторная сборка и тестирование:** `dotnet build` (0 ошибок), `dotnet test` (все тесты пройдены).
10. **Вывод:** Симптом (неверный итоговый остаток) был вызван опечаткой в операторе присваивания. Использование `+=` вместо `=` решило проблему.
